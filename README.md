# インチキ解体業者 / Wreck Works

PCブラウザで遊べる2D物理解体パズル。道具を現場に置き、予算と保護条件を守りながら全6章・15件の解体依頼に挑みます。

## GitHub Pages に公開する

1. このフォルダーの中身を GitHub リポジトリのルートに置きます。`.github/workflows/pages.yml` も含めます。
2. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択します。
3. `main` にプッシュすると、テストとビルドの後にゲームを公開します。初回に自動実行されなかった場合は、**Actions → Publish game to GitHub Pages → Run workflow** を実行します。

公開URLは **Settings → Pages** に表示されます。ローカルでは Node.js 24 で `npm ci` と `npm run dev` を実行し、表示されたURLで遊べます。別の静的ホストに配置する場合は、`npm run build` で生成した `dist/` の中身を使用します。

プレイ記録はブラウザに保存されるため、公開先のURLが変わると、そのURLでは新しい進行記録になります。

## 開発

Node.js 24 と npm を使用します。

```sh
npm ci
npm run dev
npm test
npm run build
```

ビルド成果物は `dist/` に出力されます。静的ホストにはこのディレクトリを配置します。GitHub Pages ではビルド後の `dist/` を Pages のデプロイ用アーティファクトに指定できます。相対ベースパスでビルドするため、リポジトリ配下のURLでも動作します。

## 実装

- `src/stages.ts` は、部材・接合部・設置点・材料・予算・クリア条件を定義します。
- `src/physics.ts` は、Planck の固定60 Hzステップと接触・拘束反力によるゲーム用損傷を扱います。破断すると該当する接続が外れ、残った接続で部材が動きます。解体率は、地面への構造的な接続を失い、敷地内の低い位置で静止した部材を初期質量で重み付けします。
- `src/structure.ts` は初期接続と理想化した梁の反力・たわみの概算を扱います。実行中の運動はPlanckが計算します。
- デバッグ表示から全ステージの直接選択、接合部負荷と損傷の表示、一時停止中の1ステップ実行ができます。

## 簡略化した点

柱や梁は剛体です。屋根の輪郭、窓、階段は断面図の参照表示です。切断機は接合部向けです。部材途中の切断・細分化、実建物の全体骨組解析、材料の塑性変形、詳細な周辺建物の形状評価、効果音は対象外です。落下の制御や破断限界はゲーム用に調整しています。

### 大型現場の計測

Node.jsで、表の攻略配置と60 Hzの物理更新を使った1回の計測です。描画時間は含みません。衝突数には連続した接触で発生するサンプルも含まれます。

| 依頼 | 階数 | 動的剛体 | 初期接合部 | 高インパルス接触サンプル | 物理ステップ p95 |
|---|---:|---:|---:|---:|---:|
| 10 | 5 | 38 | 49 | 1,804 | 0.67 ms |
| 11 | 2 | 26 | 34 | 514 | 0.48 ms |
| 12 | 3 | 19 | 23 | 697 | 0.44 ms |
| 13 | 3 | 21 | 27 | 488 | 0.69 ms |
| 14 | 4 | 33 | 40 | 1,847 | 0.69 ms |
| 15 | 8 | 57 | 72 | 11,934 | 1.32 ms |

製品版の通常の依頼一覧は15件です。以前の20階の建物は引き続きカメラ検証用です。進行保存はバージョン2で、試作版から対応する3件の最高評価を引き継ぎます。章間の劇や長い会話は今後追加できるよう、依頼主の短い会話を現場データで管理します。
